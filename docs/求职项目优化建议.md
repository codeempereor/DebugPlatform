### ⚠️ 但面试会被追问、当前缺少"可量化可落地证据"的地方
（这些是优化的主战场，按 ROI 排序）

1. **多线程架构说辞不够硬**：
   - 目前 grep `QThread|moveToThread|QtConcurrent` 只有 2 处，且全部是 `QTimer::start`

3. **代码健壮性缺少"错误注入"证据**：

   - 数据监控表格没有数值渲染（没有把 123.456 作为 float 高亮，NaN/溢出不标红）
   - 关于"报文解析视图不直观"：这正是用户刚才提的问题（日志 hex 纯字符串），属于面试官看了会"减分的小细节"

   - 面试官一句"这个 10 万点/秒你是怎么测出来的？"如果答不上来就会被认为是"编的"
6. **项目交付物不完整**：

   - 缺少 "README.md"（简历里 GitHub 链接点进去，必须第一眼能看到项目介绍）
   - 缺少 "Releases / 发布包"（把 DebugPlatform.exe + 依赖 Qt dll + 数据文件 打包成 zip，面试官双击就能跑，**这一项极加分**）

   - `resume_highlights.md` 第 9 行写 "技术栈: C++11 / Qt 6 / CMake"

## 三、P1 推荐做（3-5 天，决定项目"能不能过二面/HR 面"）

### P1-1 🟠 多线程架构落地（实际把 IO 移到工作线程）—— 1.5 天
**问题**：当前 QSerialPort/QTcpSocket 都在主线程。简历写"多线程与信号槽 UI 完全解耦"但不实。
**建议做法（面试标准套路）：**
1. 新建 `WorkerThread : public QThread`（或 QObject + moveToThread），把每个设备的 ICommunication 实例 moveToThread
2. ServiceLocator 里创建线程池（每设备 1 线程，或共享线程池 QThreadPool）
3. 跨线程调用全部用信号槽（避免直接调用成员函数）
4. 每个线程启动/停止/错误信号都绑定 context 版 singleShot（防止析构后回调 crash）
5. 线程内任何 new 出来的 QObject 都把 parent 设为线程对象（线程结束自动 delete）

**简历可以升级写**：
> "使用 moveToThread 将每个设备的通信实例独立移到工作线程，实现 10 设备 × 独立 IO 线程 + 主线程仅做 UI，彻底避免 IO 阻塞导致 UI 卡顿；QTimer 单射回调全部绑定 context 防止析构悬空回调，程序 7×24 小时运行无崩溃。"

### P1-2 🟠 指针安全全面升级 —— 1 天
1. 所有"非所有权引用指针"（跨模块持有、不负责 delete）替换为 `QPointer<T>`：
   - 例子：MainWindow 里的子组件指针如果有被其它模块通过 lambda 捕获 this 的风险，就把 QObject* 裸引用改成 QPointer
2. 所有权对象：能用 parent-child 的就不改（Qt 风格）；如果是手写 new/delete 的独立对象（如 ServiceLocator::shutdown 里手动 delete 的 4 个），改成 `QScopedPointer<T>` 或 `std::unique_ptr<T>`，shutdown 里就不用写 4 行 delete。
3. 所有捕获 `this` 的 lambda + 延迟执行（QTimer singleShot / queued invoke / QtConcurrent）必须加 context 对象：
   `QTimer::singleShot(delay, this, [this](){...});`（第 2 个参数传 this）
   这个改完，面试官问"析构后回调崩溃怎么办"你就能说"全部 QPointer + context-bound timer"。

**简历可以升级写**：
> "全项目裸指针 0 悬空：非所有权引用统一使用 QPointer 自动置空；延迟回调全部显式绑定 context QObject；所有权对象采用 QScopedPointer/parent-child RAII，避免析构时序错误；单元测试里加入"析构 + 待触发 timer"组合用例，程序无崩溃无断言。"

### P1-3 🟠 健壮性补齐：错误 / 超时 / 异常单测 —— 1 天
新增 15-20 个单测（覆盖以下 Case）：

| 类别 | 建议用例 |
|------|----------|
| BinaryFrame 错误帧 | CRC 错误的帧（不触发 frameReceived，触发 parseError） / 半帧 Header（只喂 0xAA，state 保持 WAIT_HEADER_2） / 超长 Length（Length=65535，触发 MAX_FRAME_SIZE 保护） / 乱序字节（搜索下一帧头同步） |
| Modbus RTU 异常响应 | 功能码 0x83 + 异常码 0x02（Illegal Data Address）→ resp.isException = true，exceptionCode 正确 |
| Modbus TCP 粘包 | 缓冲区一次性塞 3 个完整 MBAP 帧 → 解析器应 3 次独立解析出 response，字节残留为 0 |
| Modbus TCP 半帧 | 缓冲区只塞 5 字节 MBAP 头 → 不触发解析；再塞 10 字节 → 完整出 1 帧 |
| MQTT 异常 | CONNACK 返回非 0 码（连接被拒绝）→ 正确识别并上报 / SUBACK 失败（未订阅成功）→ 重试或上报 |
| 数据库 | SQLite 连接断了再 insertRegisterData → 返回 false 写日志不崩溃 |
| 重连控制器 | 连续 10 次 open 失败 → attempt==10 停止；第 11 次手动触发 start() 计数重置 |

**为什么 P1？**
这一类"错误处理"用例在面试里非常加分——因为应届生几乎所有人都只测 Happy Path。你测了错误路径，说明你具备"工程思维而非玩具项目思维"。当前 80.87% 行覆盖率，补完这一批很容易冲到 85%+。

### P1-4 🟠 数据监控表格可视化增强 —— 1 天
当前 DataMonitorWidget 只是一个普通 QTableWidget。建议加：
1. **数值变色渲染**：
   - 值为 NaN / 异常 → 红底
   - 值是寄存器地址首次接收 → 绿色闪烁一次（新值提示）
   - 值变化超过 ±10%（相对上次）→ 黄色高亮
2. **地址分组**：同一设备的寄存器可以按"组名"折叠（如 "传感器组 0-15"、"控制组 16-31"），通过一个 QTreeView 代替 QTableWidget 就能做
3. **数值类型列**：新增"类型/单位"2 列（uint16 / int32 / float / 摄氏度 / RPM）—— 配套 FR-9 提到的寄存器 JSON 配置
4. **实时曲线图**（可选，2 小时）：
   双击任意寄存器，弹出一个小窗口用 QPainter 画 1 分钟的实时曲线（环形缓冲最近 600 个 100ms 采样点）。
   不用 QChart（避免额外 QtCharts 模块依赖），直接 QPainter 手画 x/y 轴 + 折线。

**为什么 P1？** UI 上"一眼就看出专业度"的东西，面试官现场看到实时曲线 / 变色渲染，比他看一个 200x300 的灰表格印象深太多。

### P1-5 🟠 日志面板报文解析视图（就是刚才那个精简计划）—— 1 天
按刚才的精简计划实现：日志里 hex 自动探测协议 → 生成颜色高亮块 + 3 列字段表（字段名 / Hex@偏移 / 值和含义）。
这是用户刚才明确反馈的"界面不直观"问题，做完正好在面试里可以讲"用户反馈 hex 看不直观 → 我设计了自动协议探测 + 8 色高亮 + 结构化字段表解析块"。
这就是一个完整的"需求 → 设计 → 落地 → 验证"小闭环，面试可以单独讲 5 分钟。

## 四、P2 加分项（7+ 天，属于"有了碾压别人，没有也不影响过面"的内容）

### P2-1 🟢 拓展协议：Modbus UDP + MQTT 优化（2-3 天）
- **Modbus UDP**：在现有 Modbus TCP 协议栈基础上，将 MBAP 报文通过 UDP 发送，实现无连接的 Modbus UDP 通信，适用于对实时性要求高、允许丢包的场景
- **MQTT 性能优化**：当前手写协议栈已达 25,700 msg/s，可进一步优化：
  - 使用 QThreadPool 处理消息解析
  - 批量 ACK 机制
  - 自适应 QoS 降级策略
  - 这一步能把"多协议"从 4 种扩展到 5 种，MQTT 性能也有面试谈资

### P2-2 🟢 脚本化调试能力（3-4 天）
引入 **QJSEngine（Qt 自带 JavaScript 引擎）**，实现"脚本面板"：
- 用户可以写简单 JS 脚本：
  ```js
  // 例子：每次读保持寄存器 0-9，判断值 > 3000 就写寄存器 100 = 0x0001（报警）
  const resp = modbusRtu.readHoldingRegisters("modbus_rtu_dev", 1, 0, 10);
  if (resp.values.some(v => v > 3000)) {
      modbusRtu.writeSingleRegister("modbus_rtu_dev", 1, 100, 0x0001);
      sleep(1000);
  }
  ```
- 提供脚本保存/加载/循环执行（间隔可设）。
- **简历杀手级话术**："基于 QJSEngine 实现脚本化调试，支持循环执行/条件分支/定时执行，一条脚本替代 30 次手动点击操作，批量回归测试效率提升 20×。"

### P2-3 🟢 代码质量静态分析集成（1-2 天）

### P2-4 🟢 协议时序图 / 实时波形图（2-3 天）
像 Wireshark 一样的"Flow Graph"：
